# استقبال ملفّات BioTime عبر SFTP

**الجهاز يرفع ولا يدخل.** جهاز البصمة يصدّر ملفّاته دوريًّا عبر SFTP فيحتاج
حسابًا **بكلمة مرور** — والنظام يمنع دخول SSH بكلمة مرور (ق-264). فالاستثناء
**لمجموعة `biotime` وحدها**، مقيَّدًا بثلاثة: `internal-sftp` بلا صدفة،
و`ChrootDirectory` فلا يرى إلا مجلّده، وصدفة `nologin`.

## متى يُنشأ

**عند تسجيل أوّل جهازٍ للشركة — بطلبها** (قرار جواد). ولا يُنشأ للجميع
استباقًا: حساباتٌ لا تُستعمل بابٌ بلا حارس.

**ولا يُنشئه النظام بنفسه**: إنشاء مستخدمٍ يحتاج root، **وفتحُ بابٍ من الحاوية
إلى نظام التشغيل ثغرةٌ أخطر ممّا يحلّ**. فالشركة تُسجّل جهازها، ويصل المشرفَ
طلبٌ، ويُشغّل السكربت بيده.

## الإنشاء

    sudo bash scripts/add_biotime_sftp.sh <company_id>

يُخرج المستخدم (`bt<id>`) وكلمة مرورٍ **تُعرض مرّةً واحدة** — تُسلَّم للشركة
لتضبط بها الجهاز.

## البنية

    /srv/biotime/bt<id>/          <- ملكُ root (يشترطه chroot)
                  upload/         <- الجهاز يكتب هنا
                  archive/        <- النظام ينقل إليه بعد القراءة (ق-44)

**والملف يُنقل لا يُحذف**: من يشكّ في بصمة يعود للملفّ الأصليّ.

والمجلّد موصولٌ للحاوية في `docker-compose.yml`، ومهمّة
`attendance.pull_biotime_files` تقرؤه **كل خمس دقائق** — فالانتظار ساعةً يعني
موظفًا يبصم ولا يرى بصمته.

## الحذف

    sudo userdel bt<id> && sudo rm -rf /srv/biotime/bt<id>

## التحقّق

    sudo sshd -T -C user=jawad | grep -i passwordauth    # لا بدّ: no
    sudo sshd -T -C user=bt<id> | grep -i passwordauth   # yes — للجهاز وحده
